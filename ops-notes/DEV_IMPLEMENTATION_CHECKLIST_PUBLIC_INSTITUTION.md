# 공공기관 접속 이슈 대응 체크리스트 (개발 실행용)

## A. 범위 확정
- [ ] 공공기관에서 실패하는 URL/페이지 목록 확정
- [ ] 기능 유형 분류: 조회형 / 입력형(신청, 신청확인)
- [ ] 우선 전환 대상 정의: 아카데미 신청/신청확인

## B. 장애 가시화
- [ ] API 호출 실패 공통 핸들러 적용
- [ ] 사용자 안내 문구 표준화 (기관망 정책 가능성 포함)
- [ ] 재시도 버튼/대체 접수 경로 노출
- [ ] 콘솔/네트워크 에러 코드 수집 포인트 추가

## C. 서버리스 중계 API 설계
- [ ] 엔드포인트 정의
  - [ ] POST /api/academy/apply
  - [ ] POST /api/academy/check
- [ ] 요청/응답 스키마 정의
- [ ] CORS 허용 origin 제한
- [ ] rate limit 및 basic bot protection 적용
- [ ] 비밀값(토큰/키) 환경변수 처리

## D. Apps Script 연계
- [ ] 기존 Apps Script 액션/파라미터 정리
- [ ] 중계 API -> Apps Script 전달 로직 구현
- [ ] Apps Script 측 토큰 검증(가능하면) 추가
- [ ] 시트 저장 성공/실패 응답 표준화

## E. 프론트엔드 전환
- [ ] 신청 폼 호출 URL을 Apps Script 직접 호출에서 중계 API로 교체
- [ ] 신청확인 호출 URL도 중계 API로 교체
- [ ] 실패 시 사용자 메시지/대체경로 일관성 확보
- [ ] 타임아웃/재시도 정책 반영

## F. 조회형 데이터 개선 (병행)
- [ ] 우선순위 높은 조회 페이지 선정
- [ ] JSON 캐시 생성 스크립트 구성
- [ ] GitHub Actions 주기 배포 파이프라인 구성
- [ ] 런타임 Google 직접 호출 점진 축소

## G. 테스트
- [ ] 일반망 기능 정상 동작 테스트
- [ ] 공공기관망(가능하면 실제 환경) 테스트
- [ ] 실패 시나리오 테스트
  - [ ] DNS/접속 차단
  - [ ] CORS 차단
  - [ ] 타임아웃
- [ ] 데이터 정합성 테스트(신청 -> 시트 저장 -> 신청확인 조회)

## H. 운영 전환
- [ ] 롤아웃 방식 결정 (기능 플래그/점진 배포)
- [ ] 모니터링 지표 설정
  - [ ] 성공률
  - [ ] 평균 응답시간
  - [ ] 에러율
- [ ] 장애 대응 담당자/연락체계 문서화

## I. 클라이언트 커뮤니케이션
- [ ] 단기 안내문 배포
- [ ] 중기 개선 일정 공유
- [ ] 검증 결과 리포트 템플릿 준비

## J. 완료 기준 (Definition of Done)
- [ ] 공공기관망에서 신청/신청확인 정상 동작 확인
- [ ] 장애 시 사용자 안내 및 대체 경로 정상 노출
- [ ] 운영 로그로 원인 추적 가능
